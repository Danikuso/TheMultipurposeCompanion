# Frontier official online data sources (CAPI, Galnet, feeds) and Elite Dangerous game state as of October 2026

Research date: 2026-10-17. PC/Windows focus. Items marked **[OUTDATED]** or **[UNVERIFIED]** are flagged explicitly. "Probed" = I issued the HTTP request myself on 2026-10-17 (the URL itself is the source).

## 1. CAPI authentication, token lifetimes and application registration

### Takeaway
CAPI uses OAuth2 Authorization Code + PKCE at `https://auth.frontierstore.net`; a desktop app needs only a Client ID (no secret) but must first be approved by Frontier via the User Portal "Developer Zone" (not instant). Access tokens last 4 h; refresh tokens rotate on every use and stop working about 25 days after the original authorisation. The full Developer Zone docs are login-walled, so registration/redirect-URI rules rest on community notes plus working client code.

### Cited Findings
- Frontier's own OAuth2 page (dated 2019-01-22) says the Auth service is a standard OAuth2 provider, base URL `https://auth.frontierstore.net`, routes `/auth`, `/token`, `/decode`, `/me`; PKCE is supported "which allows logins from client side applications". — [Frontier OAuth2 instructions](https://hosting.zaonce.net/docs/oauth2/instructions.html) **[page itself dated 2019; still referenced by current clients, see EDDiscovery code]**
- Scopes: `auth` (default: email, first/last name, third-party user ID, platform) and `capi`. Audience (comma-separated, lowercase): `xbox`, `psn`, `steam`, `frontier`, `all` (default). — [Frontier OAuth2 instructions](https://hosting.zaonce.net/docs/oauth2/instructions.html)
- Epic was added as a usable audience by EDMC 4.2.0 ("Adds Steam and Epic to the list of audiences"); EDMC's current code requests `audience=frontier,steam,epic`, `scope=auth capi`, `code_challenge_method=S256`, `response_type=code`. — [EDMC ChangeLog.md](https://github.com/EDCD/EDMarketConnector/blob/main/ChangeLog.md); [EDMC companion.py](https://github.com/EDCD/EDMarketConnector/blob/main/companion.py). EDDiscovery's client uses `audience=all` and `scope=capi auth`. — [EDDiscovery CAPI.cs](https://github.com/EDDiscovery/CAPI/blob/master/CAPI/CAPI.cs)
- `auth` scope is mandatory alongside `capi`: since 2023-03-21 asking only for `scope=capi` yields tokens that CAPI rejects with `401 "Authentication token incomplete"` (missing email/firstname/lastname). — [FDevIDs "Frontier API" README](https://github.com/EDCD/FDevIDs/blob/master/Frontier%20API/README.md)
- Registration: developer must "apply for access" at `https://user.frontierstore.net/`; approval is "not instant"; afterwards the "Developer Zone" lists clients (scopes AUTH and CAPI) and "View" reveals Client ID and Shared Key (regenerable). Developer docs live at `https://user.frontierstore.net/developer/docs`. — [Athanasius fd-api oAuth2 notes](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-oAuth2-notes.md) (also mirrored in [EDCD/FDevIDs Frontier API folder](https://github.com/EDCD/FDevIDs/tree/master/Frontier%20API)). Probed 2026-10-17: `https://user.frontierstore.net/developer/docs` returns only a login prompt when unauthenticated, so the current docs/form could not be read. EDMC's source comment pointing to `https://auth.frontierstore.net/client/signup` now returns HTTP 404 (probed) — [EDMC companion.py](https://github.com/EDCD/EDMarketConnector/blob/main/companion.py).
- Client secret: "You only need the client_secret if using non-PKCE Authorization." EDMC's token and refresh requests send only `client_id` + `code_verifier`/`refresh_token` (no secret). — [fd-api oAuth2 notes](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-oAuth2-notes.md); [EDMC companion.py](https://github.com/EDCD/EDMarketConnector/blob/main/companion.py)
- Token flow (community-documented): `POST https://auth.frontierstore.net/token`, `Content-Type: application/x-www-form-urlencoded`, body `redirect_uri, code, grant_type=authorization_code, code_verifier, client_id`; response has `access_token`, `refresh_token`, `token_type: Bearer`, `expires_in` (14400 s = 4 h). CAPI calls use `Authorization: Bearer <token>`. — [fd-api oAuth2 notes](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-oAuth2-notes.md)
- PKCE gotcha: per the community notes the `code_challenge` MUST have trailing `=` stripped, while the `code_verifier` sent to `/token` MUST keep its `=`; otherwise `{"message":"An error occured.","logref":...}`. Frontier's page only says "Base64URL" and "binary SHA-256, not hex". — [fd-api oAuth2 notes](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-oAuth2-notes.md); [Frontier OAuth2 instructions](https://hosting.zaonce.net/docs/oauth2/instructions.html)
- Refresh: `grant_type=refresh_token&client_id=...&refresh_token=...` to `/token`; "The refresh token will be updated each time a new access token is requested" (store the newest one); refreshed tokens may omit third-party details; refresh tokens can expire → re-authorise. — [Frontier OAuth2 instructions](https://hosting.zaonce.net/docs/oauth2/instructions.html)
- 25-day cap: community notes state any refresh token works "at most 25 days after the initial Authorization"; EDMC's current troubleshooting wiki confirms "25 days after you approved this application the Frontier authorisation server will force us to get you to authorise us again." EDMC 5.13.0 added an option to iterate over all known CMDRs to keep Frontier Auth valid. — [fd-api oAuth2 notes](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-oAuth2-notes.md); [EDMC Troubleshooting wiki](https://github.com/EDCD/EDMarketConnector/wiki/Troubleshooting); [EDMC ChangeLog.md](https://github.com/EDCD/EDMarketConnector/blob/main/ChangeLog.md)
- Tokens are encrypted JWTs (JWE); revoking a client does not invalidate an unexpired access token; `/decode` and `/me` return the user record. EDMC calls `/decode` after login and rejects the session if `usr.customer_id` (as `F<id>`) does not match the journal's FID. — [fd-api oAuth2 notes](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-oAuth2-notes.md); [EDMC companion.py](https://github.com/EDCD/EDMarketConnector/blob/main/companion.py)
- Redirect URI options in real use: (a) custom protocol — EDMC on frozen Windows builds uses `edmc://auth`, received through a Windows DDE protocol handler; (b) loopback — EDMC from source/Linux starts `HTTPServer(("localhost", 0))` and uses `http://localhost:<ephemeral port>/auth`; (c) EDDiscovery uses `<scheme>://auth/` with a DDE server too. The fd-api notes say a custom URL scheme (e.g. `myapp://fd-auth-redirect`) is acceptable as long as the user's browser can reach it and the code gets back into the client. — [EDMC protocol.py](https://github.com/EDCD/EDMarketConnector/blob/main/protocol.py); [EDMC constants.py](https://github.com/EDCD/EDMarketConnector/blob/main/constants.py); [EDDiscovery CAPI.cs](https://github.com/EDDiscovery/CAPI/blob/master/CAPI/CAPI.cs); [fd-api oAuth2 notes](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-oAuth2-notes.md)
- Open-source/key policy: Frontier's FAQ says the person who obtains the API key accepts Frontier's T&Cs, "If anybody else runs an instance of your project, then they will need to obtain their own API key. This means your API key SHOULD NOT be included in your open source code." EDDiscovery's code comment: "we are not allowed to check the client ID into version control or publish it to 3rd parties" (ID supplied via env var `CAPIID`). EDMC nevertheless ships a default public Client ID (overridable via env `CLIENT_ID`). — [Frontier OAuth2 instructions](https://hosting.zaonce.net/docs/oauth2/instructions.html); [EDDiscovery CAPI.cs](https://github.com/EDDiscovery/CAPI/blob/master/CAPI/CAPI.cs); [EDMC companion.py](https://github.com/EDCD/EDMarketConnector/blob/main/companion.py); [EDDiscovery CAPI README](https://github.com/EDDiscovery/CAPI/blob/master/README.md)
- User-Agent: Frontier asked that all CAPI and Auth traffic send a custom UA matching `EDCD-[A-Za-z]+-[.0-9]+` (e.g. `EDCD-miggy-0.0.1`) so they can track problem clients; EDMC sends `EDCD-EDMarketConnector-<version>`. — [fd-api README](https://github.com/Athanasius/fd-api/blob/main/docs/README.md); [EDMC config/__init__.py](https://github.com/EDCD/EDMarketConnector/blob/main/config/__init__.py)
- Error codes: `401` = invalid/expired token (EDMC treats as "needs refresh"); `418` = service down for maintenance; `422` was the pre-Sept-2019 expired-token code. — [fd-api CAPI endpoints](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-CAPI-endpoints.md); [EDMC companion.py](https://github.com/EDCD/EDMarketConnector/blob/main/companion.py)
- Both CAPI hosts are alive: unauthenticated `GET https://companion.orerve.net/`, `/profile` and `https://legacy-companion.orerve.net/` return `401 {"status":401,"message":"OAuth Authentication Required"}` (probed 2026-10-17). `https://auth.frontierstore.net/` serves a "Frontier Authentication" page (probed).

### Inferences
- For a new open-source desktop app: register your own Client ID (PKCE public client, no secret), use `scope=auth capi`, S256, a custom-scheme or loopback redirect, and keep the ID configurable (env/config) rather than hard-coded, to respect Frontier's "don't publish your key" rule. Plan for a re-authorisation prompt at least every 25 days (or run a background keep-alive refresh).
- Because EDMC uses random loopback ports and `edmc://auth` for the same Client ID, Frontier's server evidently accepts those redirect forms for at least that client; whether a new client must pre-register redirect URIs is unknown.
- Commander rename is now possible (500 ARX), so key accounts on Frontier customer_id/FID, not commander name. — [Elite Dangerous Help FAQ](https://www.elitedangerous.com/help)

### Gaps
- Developer Zone docs/forms and any per-client redirect-URI whitelist rules are behind login; could not verify current application-approval wording, turnaround time, or whether Frontier now requires secrets for non-PKCE only.
- No official statement found on whether the 25-day refresh limit is unchanged in 2026 beyond EDMC's wiki.
- Frontier's own page does not list `epic` as an audience (only EDMC/changelog evidence).

## 2. CAPI endpoints, data, limits, reliability and third-party terms

### Takeaway
Live galaxy = `companion.orerve.net`; Legacy = `legacy-companion.orerve.net`. Documented endpoints: `/profile`, `/market`, `/shipyard`, `/communitygoals`, `/journal`, `/fleetcarrier`, `/visitedstars`, plus `/squadron` added with the Vanguards update (Aug 2025) and used by EDDiscovery but documented only in an unmerged EDCD PR. Treat CAPI as a slow, lagging, low-frequency complement to the local journal (≤1 query/min).

### Cited Findings
- Hosts: Live `companion.orerve.net` ("Since Odyssey Update 14 this only returns data for the Live galaxy"), Legacy `legacy-companion.orerve.net`, historical beta host `pts-companion.orerve.net`. — [fd-api CAPI endpoints](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-CAPI-endpoints.md); constants in [EDMC companion.py](https://github.com/EDCD/EDMarketConnector/blob/main/companion.py)
- Live vs Legacy selection in EDMC: from the journal `Fileheader.gameversion`; `>= 4.0.0` ⇒ Live host, otherwise Legacy. EDMC 5.7.0 re-enabled CAPI for Legacy players. — [EDMC monitor.py](https://github.com/EDCD/EDMarketConnector/blob/main/monitor.py); [EDMC ChangeLog.md](https://github.com/EDCD/EDMarketConnector/blob/main/ChangeLog.md)
- The root of the CAPI host lists available endpoints (needs a token): `/profile`, `/market`, `/shipyard`, `/communitygoals`, `/journal` (optionally `/:year/:month/:day`), `/fleetcarrier`, `/visitedstars` (zip of `VisitedStarsCache.dat`; HTTP 102 = still generating, retry in minutes), all with optional `?language=[en|fr|de|ru|es|pt]` where relevant. — [fd-api CAPI endpoints](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-CAPI-endpoints.md)
- New `/squadron` endpoint ("Describe the squadron your Commander is currently a member of, if any"): returns squadron identity/alignment/perks, active7/30-day counts, squadron carrier (finances, itinerary, capacity, services crew, reputation), `members[]` (ranks, last location, play time) and `bank` (credits, commodities, microresources, ships). Documented in EDCD/FDevIDs PR #103 "Update CAPI Endpoints for Vanguards update" (opened 2025-09-08, still OPEN when checked 2026-10-17; PR #102 closed in its favour). — [FDevIDs PR #103](https://github.com/EDCD/FDevIDs/pull/103) (diff: https://github.com/EDCD/FDevIDs/pull/103.diff). EDDiscovery's library implements `/squadron` (constant `SQUADRONCARRIER_URL`) and `/communitygoals`. — [EDDiscovery CAPI.cs](https://github.com/EDDiscovery/CAPI/blob/master/CAPI/CAPI.cs), [Squadrons.cs](https://github.com/EDDiscovery/CAPI/blob/master/CAPI/Squadrons.cs)
- The squadron doc states `platform` is "Only PC". — [FDevIDs PR #103 diff](https://github.com/EDCD/FDevIDs/pull/103.diff)
- `/profile` returns: commander (name, id, credits, debt, ranks incl. combat/trade/explore/cqc/empire/federation/power/soldier etc., capabilities, docked/alive), `lastStarport`, `lastSystem`, current `ship` (value breakdown, health, modules with engineering/blueprint details, launch bays) and `ships` (all owned ships; list or dict keyed by string ID). EDMC also reads `suit`, `suits`, `loadouts` from it. — [fd-api CAPI endpoints](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-CAPI-endpoints.md); [EDMC companion.py](https://github.com/EDCD/EDMarketConnector/blob/main/companion.py)
- `/market` (last docked station/carrier/settlement): commodities with buy/sell/mean price, stock/demand and brackets 0-3, legality, imported/exported/prohibited, economies, services states (`ok`/`unavailable`/`private`). `/shipyard`: outfitting modules (stock, -1 = unlimited) and ship vendor list. — [fd-api CAPI endpoints](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-CAPI-endpoints.md)
- `/fleetcarrier`: HTTP 204 if the Commander owns no carrier; otherwise carrier callsign/hex-encoded name, fuel (max 1000), state, theme, docking access, capacity breakdown, itinerary, market/black-market finances, bank/finance incl. weekly upkeep and debt threshold, crew per service, full cargo, buy/sell orders, microresource locker (on-foot goods/assets/data), reputation, market snapshot, ships and modules. — [fd-api CAPI endpoints](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-CAPI-endpoints.md). A May 2026 EDMC report shows the 204 → "empty response body" case in practice (game 4.3.3.0). — [EDMC issue #2666](https://github.com/EDCD/EDMarketConnector/issues/2666)
- `/journal`: whole-day journal for the account; 200 full, 204 nothing played that day, 206 partial (retry until 200), 401 auth. Docs say do NOT expect real-time updates and ideally query it only after a play session. — [fd-api CAPI endpoints](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-CAPI-endpoints.md)
- Rate limits (guidance, not an official published quota): "try not to issue more than one query a minute"; Frontier "in the past stated that rate limiting might kick in if you perform more than 2 queries per second"; CAPI data can lag the game. EDMC implements a 60 s minimum between sets of station queries and a 15 min cooldown for `/fleetcarrier`, default timeout 10 s (60 s for fleetcarrier), retries on 429/5xx with backoff; EDDiscovery caches `/profile` for 30 s. — [fd-api CAPI endpoints](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-CAPI-endpoints.md); [EDMC companion.py](https://github.com/EDCD/EDMarketConnector/blob/main/companion.py); [EDDiscovery CAPI.cs](https://github.com/EDDiscovery/CAPI/blob/master/CAPI/CAPI.cs)
- `/fleetcarrier` can be very slow for carriers with many cargo/orders and, in EDMC's experience, "all other CAPI queries will be blocked until the /fleetcarrier query completes" (hence the 60 s timeout). — [EDMC ChangeLog.md, Release 5.8.0](https://github.com/EDCD/EDMarketConnector/blob/main/ChangeLog.md)
- Data quirks handled in EDMC: trailing `" +"` stripped from station names; `services` sometimes an empty list instead of dict; market/shipyard ID may not match `lastStarport` right after docking ("ServerLagging"); `/shipyard` returned HTTP 500 on carriers in an older release (blamed on Frontier). — [EDMC companion.py](https://github.com/EDCD/EDMarketConnector/blob/main/companion.py); [EDMC ChangeLog.md](https://github.com/EDCD/EDMarketConnector/blob/main/ChangeLog.md)
- Reliability 2025-2026: no official status/incident page found. EDMC's tracker shows no hard CAPI outage in 2025-26, only client-side or carrier-specific issues (e.g. [#2666 fleetcarrier 204](https://github.com/EDCD/EDMarketConnector/issues/2666), [#2477 carrier data stale during colonisation hauling](https://github.com/EDCD/EDMarketConnector/issues/2477)). EDMC 6.0.0 (Dec 2025) added extra journal events that trigger a Carrier CAPI check. — [EDMC ChangeLog.md](https://github.com/EDCD/EDMarketConnector/blob/main/ChangeLog.md)
- **[UNVERIFIED]** A search summary of Inara forum threads reports July 2026 "HTTP 400 token" and HTTP 500 errors on Inara's CAPI imports that "only Frontier" could fix; I could not open the threads (HTTP 503) — see [Inara API thread](https://inara.cz/elite/board-thread/7049/287563/).
- Server-status endpoint (undocumented but live): `GET https://ed-server-status.orerve.net/` returned `{"status": "Good", "message": "", "code": 1, "product": "FORC-FDEV-DO-1000"}` via CloudFront (probed 2026-10-17). Semantics of other `code` values are unknown.
- The official Journal Manual is on v38 (file dated 2026-04-28; changelog "Changes for Odyssey up to update26 (May 2026)", only change: passenger-type statistics). v37 was May 2023. v39/v40 URLs 404. — [Journal Manual v38](https://hosting.zaonce.net/community/journal/v38/Journal_Manual_v38.pdf), [v37](https://hosting.zaonce.net/community/journal/v37/Journal_Manual_v37.pdf)
- Text search of v38 finds **no** `Colonisation*` events and no Powerplay 2.0 events (`PowerplayMerits`, `PowerplayRank`); only legacy Powerplay 1.0 events and generic `Squadron` events are documented, i.e. the official manual lags the game by years. EDMC added `PowerPlayMerits`/`PowerPlayRank` handling in 5.13.0 and handles `powerplaymerits` in monitor.py. — [Journal Manual v38](https://hosting.zaonce.net/community/journal/v38/Journal_Manual_v38.pdf); [EDMC ChangeLog.md](https://github.com/EDCD/EDMarketConnector/blob/main/ChangeLog.md); [EDMC monitor.py](https://github.com/EDCD/EDMarketConnector/blob/main/monitor.py)
- Terms: see section 5 (EULA, PII/consent, media rules).

### Inferences
- What CAPI offers that the journal does not (derived from the field lists above): full owned-ship fleet with module/engineering detail for stored ships, account-level credits/debt/ranks snapshot, suits/loadouts, complete fleet-carrier finances/orders/crew/inventory, squadron roster/bank/squadron-carrier state, per-commander Community Goal contributions, the `VisitedStarsCache.dat` archive, and remote journal retrieval. Station market/outfitting/shipyard data is largely duplicated by the journal's `Market.json`/`Outfitting.json`/`Shipyard.json` sidecar files (not covered in my sources), so CAPI is optional for those.
- Design for polling no faster than once per minute, 15+ min for carriers, tolerate 204/206/401/418/500 and stale data, and degrade gracefully when CAPI is unavailable.

### Gaps
- The live endpoint list (`GET /` with a token) could not be fetched without credentials, so additional 2026 endpoints (colonisation, Operations) cannot be ruled out; none found in EDCD/EDMC/EDDiscovery sources.
- No hard numeric rate limit from Frontier in 2025-26; no official outage history.
- `/squadron` docs are from an unmerged community PR (contains "UNCLEAR (NEED INPUT)" fields).
- Unclear whether console accounts can use CAPI (squadron doc says PC only).

## 3. How EDMarketConnector and other tools use CAPI today

### Takeaway
EDMC (v6.1.2 released 2026-01-29; 6.1.3-beta3 on 2026-05-30; repo pushed 2026-10-01) uses a deliberately minimal CAPI footprint: `/profile` + `/market` + `/shipyard` after docking, optional `/fleetcarrier`; everything else comes from the journal. EDDiscovery has a fuller C# client including `/squadron`.

### Cited Findings
- EDMC's `CAPIEndpoint` enum contains only `/profile`, `/market`, `/shipyard`, `/fleetcarrier`. Station flow: query `/profile`; if docked (or on foot) and `lastStarport.services` shows commodities/outfitting/shipyard, then query `/market` and `/shipyard`, checking the station IDs match. Worker thread + queues, 401 → refresh, 418 → "down for maintenance". — [EDMC companion.py](https://github.com/EDCD/EDMarketConnector/blob/main/companion.py)
- `/fleetcarrier` is triggered by journal events `CarrierBuy`, `StartUp`, `CarrierLocation`, `CarrierStats`, `CargoTransfer`, `MarketBuy` (when the option is enabled), with a 15-minute holdoff. — [EDMarketConnector.py](https://github.com/EDCD/EDMarketConnector/blob/main/EDMarketConnector.py)
- Releases: 6.0.0 (Dec 2025): x64 build, config.toml, EDAstro plugin, more carrier-CAPI triggers, Caspian Explorer support; 6.1.0 (Jan 2026): plugin browser, guards against expired CAPI auth in EDMC.exe; 6.1.1/6.1.2 (Jan 2026) config robustness. — [EDMC ChangeLog.md](https://github.com/EDCD/EDMarketConnector/blob/main/ChangeLog.md); release dates from [GitHub releases](https://github.com/EDCD/EDMarketConnector/releases)
- EDMC has a remote "killswitch" mechanism that can disable CAPI features (`capi.auth`, `capi.request.<endpoint>`) per version. — [EDMC Killswitches.md](https://github.com/EDCD/EDMarketConnector/blob/main/docs/Killswitches.md); [companion.py](https://github.com/EDCD/EDMarketConnector/blob/main/companion.py)
- EDMC states that CAPI Update does not affect EDSM/Inara, which are fed from journal events. — via search summary of [EDMC Troubleshooting wiki](https://github.com/EDCD/EDMarketConnector/wiki/Troubleshooting)
- EDDiscovery's `CAPI` library (Apache-2.0) covers Profile, Market, Shipyard, Journal, Fleetcarrier, Squadrons and community goals; Python reference `Athanasius/fd-api` is "not maintained as of April 4th, 2024". — [EDDiscovery/CAPI](https://github.com/EDDiscovery/CAPI); [FDevIDs README](https://github.com/EDCD/FDevIDs/blob/master/README.md)
- EDCD GitHub org remains active (FDevIDs updated 2026-09-05 per search summary). — [EDCD org](https://github.com/edcd)

### Inferences
- A Python companion can mirror EDMC's pattern (journal-first, CAPI as periodic enrichment) and borrow its OAuth/PKCE and protocol-handler design (MIT/GPLv2+ licensing of EDMC code must be checked before copying; EDMC is GPL-2.0-or-later).

### Gaps
- No evidence found of any third-party tool using CAPI for colonisation or Operations data.

## 4. Galnet and other official feeds

### Takeaway
There is no official public API for market data, but Galnet, news and community goals have working unauthenticated JSON/RSS feeds (undocumented officially; verified live 2026-10-17). Server status exists as an undocumented JSON endpoint.

### Cited Findings
- **Galnet JSON:API (Drupal 11):** `https://cms.zaonce.net/en-GB/jsonapi/node/galnet_article` — `Content-Type: application/vnd.api+json`, `Cache-Control: max-age=180, public`; supports `sort=-published_at`, `page[limit]` (50 returned per page), `page[offset]` (next link provided), `filter[field_slug]=<slug>`. Attributes: `title`, `published_at`, `body.value` (HTML), `field_galnet_date` (in-game date e.g. "15 OCT 3312"), `field_galnet_guid`, `field_galnet_image`, `field_slug`. Latest item 2026-10-15 "Brewer Corp Jump Satellite Initiative Hailed a Success". Locale variants work (`/de-DE/`, `/fr-FR/`, `/es-ES/`, `/ru-RU/`; `/pt-BR/` fell back to English). — probed 2026-10-17; original endpoint noted in [fd-api other APIs](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-other-APIs.md)
- **Galnet RSS:** `https://community.elitedangerous.com/galnet-rss` — RSS 2.0, 15 items; `<pubDate>` is identical for all items (generation time, not article date) and no `<link>` element, so use the JSON API for real dates (probed 2026-10-17). Web article URL pattern: `https://www.elitedangerous.com/news/galnet/<slug>` ([example in Oct dev log](https://www.elitedangerous.com/news/elite-dangerous-october-dev-log-2026-law-disorder)).
- **News/dev-log CMS feed:** `https://cms.zaonce.net/en-GB/jsonapi/node/news_article?sort=-published_at` — all Frontier games' news (ED dev logs, ARX/ship posts, FY results); fields `title`, `published_at`, `body`, `field_category`, `field_slug`, relationship `field_game`; supports `filter[...][condition]` on `title`/`field_slug`. ED patch-note pages (`/news/updates/4-x-y-z`, `/update-notes/4-0-<n>-<m>`) are NOT in this feed (other node-type names tried returned 404; `/jsonapi` root is 403). — probed 2026-10-17
- **Official update notes:** `https://www.elitedangerous.com/news/updates` (HTML list with dates, Next.js site; plain `WebFetch` gets HTTP 403 but a browser-like UA via curl works). Dev logs published monthly at `/news/<slug>`. — [Updates page](https://www.elitedangerous.com/news/updates)
- **Community Goals:** `https://api.orerve.net/2.0/website/initiatives/list?lang=en` (languages de, en, fr, es, pt, ru; JSON, or XML with `Accept: text/xml`). On 2026-10-17 it returned `{"activeInitiatives":[]}` (no active CG). A community mirror shows CG #861 (Brewer jump satellites, ended 2026-10-15) and CG ids 849-861 running July-Oct 2026, so CGs are still being run. Non-empty schema was not captured. — [fd-api other APIs](https://github.com/Athanasius/fd-api/blob/main/docs/FrontierDevelopments-other-APIs.md); [BirdNet CG mirror](https://elite.drinkybird.net/goals) (mirror also offers RSS at `/goals/rss?lang=en`; its `/updates` patch-note feed stopped at Aug 2023)

### Takeaway
There is no dedicated "third-party tools policy" page.
